# Jarvis v0.8 — Autonomous Engineering Runtime

v0.8 hardens long-running local and remote engineering work around explicit ownership, evidence, permissions, cancellation, and measurable execution state.

## Local execution proof

Every composed local run records a durable proof ledger under the Jarvis state directory (`$XDG_STATE_HOME/jarvis/proofs` or `~/.local/state/jarvis/proofs`). The workspace path is hashed, so proof files do not dirty the repository.

```bash
jarvis proof --workspace .
jarvis dashboard --workspace . --watch
```

Proof records cover selected routes, permission decisions, approvals, tool calls, test results, failures, and completion. They are execution evidence; they do not contain model chain-of-thought.

## Permission boundaries

Project policy can be declared in `.jarvis/permissions.toml`:

```toml
[permissions]
allow = ["apply_patch"]
ask = ["run_command"]
deny = ["browser_type"]
```

Read-only operations are allowed by default. Mutations ask by default. `plan` mode denies mutations even if a project rule would otherwise allow them. Existing CLI approval callbacks remain the authority for `ask` decisions.

## Lease-fenced cloud workers

Cloud work is attempt-scoped. Every claim receives a fresh `lease_id`. Heartbeat, state updates, and completion must present the current worker ID plus lease ID. A reclaimed task therefore invalidates the previous worker's ability to publish results.

```bash
jarvis cloud submit "fix the bug" \
  --repository-url https://github.com/example/repo.git \
  --git-commit <exact-commit> \
  --model auto \
  --write \
  --idempotency-key issue-123-attempt-1

jarvis cloud worker --worker-id build-host-1 --model auto
jarvis cloud status <task-id>
jarvis cloud cancel <task-id>
```

The worker runs the actual agent execution in a killable child process. Heartbeats retry transient transport failures with bounded backoff. If the fence is rejected or cannot be renewed before expiry, the child is terminated and its result is not published.

Git-backed tasks use per-lease ephemeral workspaces. Worker-side host allowlisting remains mandatory through `JARVIS_CLOUD_GIT_ALLOW_HOSTS`.

## Model routing

`model=auto` keeps the worker's calibrated configuration. A named configured profile switches provider, model, endpoint, output limits, and its own API-key environment. Raw model identifiers stay on the worker's existing provider/endpoint. Provider credentials are never sent in cloud task payloads.

## Background jobs and schedules

Local job cancellation terminates the complete spawned process tree rather than only the direct Python child. POSIX workers use process groups; Windows uses `taskkill /T`.

Cron schedules use conventional five-field semantics, including:

- lists, ranges, and steps;
- Sunday as `0` or `7`;
- day-of-month/day-of-week OR behavior when both fields are restricted;
- UTC evaluation and bounded next-occurrence search.

## Release gates

v0.8 is expected to pass:

1. Core Black/Ruff/pytest/coverage/build/Twine.
2. Jarvis Python 3.10/3.12/3.13, clean-wheel install, and all-runtime Black.
3. AI Stack unit/Postgres/supply-chain/model integration gates.
4. Cross-repository Core + CLI + Server Postgres smoke validation using the exact release candidates.

A cloud task is not considered safely autonomous unless stale-fence completion, lease expiry/reclaim, cancellation, idempotent submission, and restart/recovery paths are covered by executable tests.
