# Jarvis 0.10.6

## Release summary

Jarvis 0.10.6 aligns the CLI's model diagnostics with the production service boundary: Jarvis talks to AI Stack, and AI Stack talks to the dedicated jarvis-inference gateway.

## Highlights

- Fix `jarvis model-doctor` to query AI Stack's `/models/available` catalog instead of the inference-only `/v1/models` endpoint.
- Keep `/v1/*` ownership inside `jarvis-inference`; Jarvis does not treat it as an AI Stack API.
- Keep Cloudflare Access service-token support for protected AI Stack deployments.
- Preserve concrete model IDs such as `qwen3:1.7b` through the AI Stack contract.
- Keep direct inference available only through the explicit `jarvis local` diagnostic/developer path.

## Production architecture

```text
Jarvis CLI
   │
   │ AI_STACK_BASE_URL + AI_STACK_API_KEY
   ▼
AI Stack
   │
   │ INFERENCE_BASE_URL + INFERENCE_API_KEY
   ▼
jarvis-inference
   │
   ▼
Ollama
```

The Jarvis client must use the AI Stack API root. Do **not** configure the normal Jarvis client with an AI Stack URL ending in `/v1`.

## Upgrade


### pip

```bash
python3 -m pip install --upgrade jarvis-agent-cli
jarvis --version
```

```text
0.10.6
```

## AI Stack configuration

```bash
export AI_STACK_BASE_URL="https://<ai-stack-host>"
export AI_STACK_API_KEY="<ai-stack-agent-key>"
export CLOUDFLARE_ACCESS_CLIENT_ID="<service-token-client-id>"
export CLOUDFLARE_ACCESS_CLIENT_SECRET="<service-token-client-secret>"
export JARVIS_MODEL="qwen3:1.7b"

jarvis model-doctor
```

Cloudflare Access variables are only required when the AI Stack hostname is protected by Cloudflare Access. Never commit credentials.

## Validation

After upgrading, verify:

```bash
jarvis --version
jarvis model-doctor
```

A successful `model-doctor` validates the AI Stack health, capabilities, advertised concrete model, and a read-only chat request through the AI Stack boundary.
