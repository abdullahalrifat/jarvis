# Jarvis 0.10.8

## Release summary

Jarvis 0.10.8 makes `model-doctor` a layered production diagnostic for the Jarvis → AI Stack → jarvis-inference path. The default check now isolates the inference gateway from the slower full agent path, making failures actionable instead of collapsing into a generic `/chat` timeout.

## Highlights

- Probe AI Stack health, capabilities, model catalog, and the dedicated versioned `/diagnostics/inference` endpoint.
- Validate embeddings and generation directly through `jarvis-inference` without running the full agent/memory path.
- Add `jarvis model-doctor --full-agent` for an explicit end-to-end `/chat` check.
- Propagate the configured `--timeout` to remote diagnostics.
- URL-encode concrete model IDs when calling the inference probe.
- Add regression coverage for direct inference probing and model URL encoding.
- Harden the coordinated AI Stack/inference diagnostics against embedding and queue starvation.

## Production architecture

```text
Jarvis CLI
   │
   │ AI_STACK_BASE_URL + AI_STACK_API_KEY
   ▼
AI Stack
   │
   │ INFERENCE_BASE_URL + INFERENCE_API_KEY
   ▼
jarvis-inference
   │
   ▼
Ollama
```

Normal Jarvis operation continues to use AI Stack as the control plane. Direct `jarvis-inference` access remains diagnostic/developer-only.

## Validation

Run the layered diagnostic:

```bash
jarvis model-doctor
```

For the complete AI Stack agent path:

```bash
jarvis model-doctor --full-agent
```

The default command should report the AI Stack gateway and direct inference probe separately. The full-agent option intentionally exercises the slower memory/planning/`/chat` path.
