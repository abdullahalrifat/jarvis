# Jarvis v0.5 developer intelligence

## Commands

```bash
jarvis plan "Refactor authentication" --workspace . --model auto
jarvis local --plan "Upgrade the cache layer" --workspace .
jarvis tui "Fix the failing auth test" --workspace . --model auto
jarvis skills --workspace .
jarvis skills postgres-migration --workspace .
jarvis hooks --workspace .
jarvis hooks UserPrompt --workspace . --payload '{"task":"deploy"}'
jarvis bench benchmarks/v0.5-core.json --workspace . --model auto --report .jarvis/bench/latest.json
```

## Skills

Project Skills live at `.jarvis/skills/<name>/SKILL.md`. User Skills can live at
`~/.config/jarvis/skills/<name>/SKILL.md`.

```markdown
---
name: postgres-migration
description: Safely create PostgreSQL schema migrations
tools:
  - read_file
  - run_command
risk: high
model_invocable: true
---

Inspect existing migrations first. Require a rollback path and run migration tests.
```

Only metadata is indexed initially. Full Skill bodies are loaded when task terms match
skill names/descriptions or when a Skill is explicitly inspected.

## Hooks

Hooks live in `.jarvis/hooks.toml` or `~/.config/jarvis/hooks.toml`.

```toml
[[hook]]
event = "PreTool"
command = ["python", "scripts/check_tool.py"]
when_tool = "run_command"
timeout = 5
required = true

[[hook]]
event = "TaskComplete"
command = ["python", "scripts/record_completion.py"]
timeout = 10
```

Hook programs receive a JSON payload on stdin. A JSON response may contain:

```json
{"allow": true, "add_context": "policy checked", "require_approval": false}
```

Required hooks fail closed. Runtime hooks cover model calls, tool calls, mutations,
tool failures and the high-level session/task events used by plan/TUI execution.

## Sandbox and network policy

`.jarvis/sandbox.toml`:

```toml
[sandbox]
mode = "auto"

[sandbox.network]
mode = "allowlist"
allow = ["github.com", "pypi.org"]

[sandbox.filesystem]
readonly = ["~/.m2", "~/.gradle"]
writable = ["."]
```

Supported network modes are `deny`, `allowlist`, and `allow`. Linux uses bubblewrap
when available and macOS uses sandbox-exec. `mode = "required"` fails closed when
platform isolation is unavailable.

## Repository graph and LSP

`repository_map` now updates `.jarvis/graph/repository.sqlite3` incrementally. It stores
file digests, symbols, imports and source-to-test relationships and enriches bounded
source files with persistent language-server data when a supported server is installed.

Recognized servers include pyright, typescript-language-server, gopls, rust-analyzer,
clangd and Metals. The persistent client exposes document lifecycle, definitions,
references, implementations, type definitions, hover, signatures, diagnostics, rename,
code actions, formatting and workspace symbols.

## Benchmarks

The benchmark report includes task success rate, incorrect-completion rate, median and
p95 latency, per-category scores and per-case failures. `compare_reports` can gate a
candidate result against a baseline with success and latency regression thresholds.

The checked-in `benchmarks/v0.5-core.json` is the representative corpus definition.
Cases that declare `metadata.requires_fixture` are intended to run against a seeded
fixture repository in the integration/evaluation environment rather than arbitrary
production workspaces.
